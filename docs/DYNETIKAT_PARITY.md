## Checkpoint 1: checked raw input

Run from `lean/`:

```sh
lake build DyNetKAT
lake env lean --run DyNetKAT/Main.lean validate path/to/input.json
lake env lean --run test_v11_input.lean path/to/pinned-corpus
```

The first validation command accepts multiple paths and returns status 1 if
any input fails. The corpus test expects the three original JSON fixtures
and all 24 outputs generated by the pinned `benchmarks/fattree.py` with its
sibling `util.py`. Run the generator in that corpus directory. The
verification for this checkpoint used Python 3.11.15 with NetworkX 3.6.1 for
generation. Lean alone checks the generated JSON. All three original fixed
fixtures and all 24 generated inputs passed, with zero rejected or
unexercised. The test checked all 120 query entries, declaration and
channel names, and FatTree field names and selector nesting.

- `Frontend/V11Json` decodes the original seven input fields. It retains
  input object order and rejects duplicate JSON keys before any lookup.
  `V11Syntax` parses quoted dup-free NetKAT, including tests, assignment,
  negation, union, composition and star. The process grammar recognizes
  packet, send, receive and reconfiguration prefixes, names, deadlock,
  choice, parallel, both merges, delta and pi.
- `V11Loader` resolves channels, parses selectors and elaborates the whole
  input over one dependent `PacketSchema`. Raw v1.1 files have no supplied
  field declarations. The loader collects field names and maximum literals
  from every policy, payload and query operand, sorts the field names,
  and gives a field with maximum literal `n` the finite domain
  `0 .. n+1`. This keeps an unmentioned value available to complement
  tests even when all lower values occur. This is the loader's finite
  interpretation, independent of the reference adapter's comparison-local
  binary widths. The typed elaborator also checks names and bounds when
  given explicit domains. It builds no Cartesian packet universe.
- Executable Lean decisions check defined references, paper continuation
  sorts and guarded defining bodies. Successful validation constructs
  `Program true env` and its finite-support certificate over the checked
  declarations. The implementation checks every declared body, including
  unreachable ones. The existing `RecEnv`, SOS and administrative lookup
  remain the downstream semantics.
- Queries retain packet key, zero-based index, depth, ordered tail stage
  sets, original selector and third-operand text, and the typed polarity
  or waypoint test. Head with no tails has an empty stage list. Selector
  text does not specify a star variant. Stars stay in the policy AST for
  a later consumer of the selected head.
- Payload equality is syntactic in the typed NetKAT AST. Whitespace and
  redundant grouping delimiters are parser notation. Distinctions in
  constructors, operator order and nonredundant grouping remain, even
  for equivalent policies. There is no textual zero replacement or
  implicit insertion of reference preprocessing restrictions. Exact
  agreement with the old string backend on formatting-sensitive matches
  is a differential checkpoint concern.
- The loader gives explicit errors for malformed inputs, invalid packet
  tests, undeclared channels/references, unguarded definitions, invalid
  continuations, rcfg restrictions and unsupported query syntax. It
  handles raw JSON only. Preprocessed `comm` or `file_name` metadata is
  rejected until the checked reuse checkpoint.

The ledger below records the audited baseline. Checkpoint 1 closes its
raw JSON, NetKAT text, process text, channel/declaration admission and
packet-predicate intake gaps, and supplies the parsed half of selector
and query handling. Checkpoint 2 must apply exact finite projection and
checked head/tail extraction to this package, then dispatch `!0` and
`=0` with the declared depth.

## Checkpoint 2 bounded reachability

From `lean/`, run:

```sh
lake build DyNetKAT
lake env lean --run DyNetKAT/Main.lean reach path/to/input.json
lake env lean --run test_v11_reachability.lean path/to/pinned-corpus/*.json
```

The native `dynetkat reach` command accepts the same arguments. It visits
reachability queries in the loader's packet-key and tuple order. It reports
`nonempty` separately from `satisfied`. The latter compares the Boolean
to the requested polarity, true for `!0` and false for `=0`. Both refer
only to the original depth. Non-verdicts carry diagnostics and make the
command exit unsuccessfully. A violated property is a verdict. The runner
skips waypoint entries.

`BoundedQuery.elaborate` maps a head to no stages and each nested tail to
one finite set of literal typed reconfigurations in inner-to-outer order.
The loader checks channel names and parses payload structure. A tail event
set accepts rcfg actions. Packet actions arise from the head policy, and
send/receive prefixes participate in exact row construction and matching.
Standalone sends and receives do not belong to selected visible words.
The general adapter applies `projectedReachability_correct`, whose
head/tail interpretation uses `graphTails_head_iff` and
`graphTails_feasible_iff`. Packet-list effects follow the existing
`SourceTrace` correspondence. The bound includes every packet step and
selected synchronization. Reference lookup is administrative. The
current adapter rejects explicit source restrictions with a classifier
diagnostic. The corpus needs no explicit source restriction.

For a query whose ingress pins one packet and whose depth is the number
of tail layers plus one, `tightReachability` proves that every selected
word has exactly one reconfiguration per tail and one final packet step.
It traverses the existing exact checked rows and applies the supplied-packet
NetKAT evaluator only to candidate final movements. This avoids building a
global relation for each FatTree starred policy. The fast path and general
path return the same proposition, `EndpointReachable` at the supplied
bound. Successful results carry its equivalence to the nonempty Boolean.
True recovers existential source-trace evidence in Lean and false proves
bounded emptiness. Execution exposes no concrete witness serializer.

## Query meaning and compatibility discrepancies

For both polarities, apply the requested fourth-item depth to the complete
DyNetKAT trace, including prior packet steps and selected reconfigurations.
NetKAT star within one packet action retains its own exact semantics.
An empty list of stages means direct head extraction. Head unions packet
policies before the first reconfiguration on each branch. Each tail retains
continuations at matching reconfigurations and may continue scanning matching
events. An event outside the current set cuts that scan. Repeated tails apply
to the previous tail's result. A stage set is a set of allowed events, with
no universal ordering or arbitrary regular-expression path language inside
a stage. A zero/nonzero result at depth n says nothing by itself about larger
depths. Reuse `projectedReachability_correct` for endpoint results. For
waypointing, expose and prove the policy-level extraction bridge, so the
full extracted relation remains available for composition. A Boolean
reachability result alone cannot supply it.

For starred `N = H*` (normally `H = p · t`), define
`A = in · N · out` and
`B = in · (¬out · H)* · w · (¬in · H)* · out`.
For an unstarred expression, the reference prepends the two guards to
separate copies of N and has
`B = in · (¬out · N) · w · (¬in · N) · out`.
The reference tests `A + B ≡ B`, which is `A ⊆ B`. An empty A satisfies
inclusion. A bypass can coexist with a waypoint route for the same endpoint
pair. Extractor branching can produce several policies, so audit the actual
resulting head shape before treating a printed star as a top-level star.
The reference searches for any `*`, splices at the first opening
parenthesis, and strips parentheses in endpoint guards. Preserve the
well-defined formulas structurally. Ambiguous shapes need a precise
unsupported result or independently justified translation. In particular
a waypoint predicate is inserted between the two guarded passes, with the
guard placement preserved. See pinned `src/python/dynetkat.py`.

Track discrepancies explicitly in the differential manifest.

- In the reference, `DNA` and Maude rewriting accept auxiliary or unchecked
  forms. The Lean loader constructs an admitted `Program`, respects packet
  continuation sorts and guarded reachable definitions, and analyzes only
  its SOS residuals. In particular, the artifact accepts delta sets that
  block rcfg terms, while the paper restriction set contains send and
  receive actions. Such a restriction needs a compatibility diagnostic.
- The raw v1.1 encapsulation scan sees recursive bodies only. It can miss
  direct root communication and its zero replacement can affect identically
  spelled communication payloads. Keep payloads syntactic and perform zero
  elimination only at packet prefixes with verified zero. Compare the
  effective reference restriction with the verified block-all unilateral
  communication route on each fixture. If literal restriction differs, use
  a checked exact restriction where meaningful or record the discrepancy.
- Preserve the lexical identity relevant to literal fixture matches across
  declarations, communication and selector tokens. Test whitespace and
  grouping collisions where quoted reference strings differ but the typed
  payload ASTs agree. A compatibility layer must establish match
  preservation or diagnose the discrepancy. Semantic NetKAT equality
  cannot identify communication payloads.
- Reference head/tail rewrites traverse sequential syntax after preprocessing.
  A result caused by an infeasible prefix, stuck Maude reduction or
  unchecked rewrite requires a discrepancy entry before comparing verdicts. Compare normalized
  selector results with the feasible trace reading and record disagreements.
- Accept valid singleton declaration maps and constant-only NetKAT policies.
  The reference's dictionary-key indexing and IDD `max(digits)` failures
  are accidental. The README also records an IDD union-associativity
  failure and suggests trying the automata adapter. Reject malformed selectors and unsupported query shapes
  explicitly and test both. Duplicates, unsafe file names, unknown channel
  references and resource limits need deterministic diagnostics.
- Preprocessed files can encode prior lossy rewrites. Validate them as
  supplied and track their provenance. A successful load alone does not
  certify that they preserve the semantics of an unavailable raw source.

## Acceptance and progress estimates

**Functional parity** is complete when unmodified pinned raw JSON files
and their valid preprocessed counterparts load directly, every supported
tuple has a checked bounded verdict with stable identity, and the documented
CLI covers batching, worker counts, preprocessing reuse, help, diagnostics
and timing display. The comparison run must cover 12 queries across the
three fixed inputs and 108 dispatches across the 24 FatTree files (54 in
separate groups plus 54 in combined files). Compare by packet ID, index,
query meaning and depth. Every case must either match the pinned tool or
have an explicit discrepancy with a checked Lean interpretation and a
regression. A crash, timeout or unclassified verdict difference cannot be
counted as a matching success. Require raw/reused and serial/parallel
agreement for the same admitted query, and negative regressions for invalid
inputs. Success-line compatibility and native invocation/exit differences
are documented separately. Maude, KATch and external NetKAT binaries are
reference-run dependencies only.

**Empirical parity** is complete when the recorded campaign includes all
six scales and all four query groupings, archives original and regenerated
artifacts with literal differences explained, and reports ten repetitions
per configuration with declared hardware, dependencies, worker counts and
reuse settings. Preserve raw measurements, reference and Lean outcomes,
timeouts and memory. Report the individual/combined timings, preprocessing
and decision shares, and scaling comparison. Timing differences do not
invalidate a functional verdict.

**Planning estimate.** Functional parity was about **40%** at the audit.
After checkpoint 1 it was about **70%** as implementation readiness.
The bounded reachability implementation raises that estimate to **80%**. Score 10
equally weighted capabilities at 0 for absent, 0.5 for a verified reusable
core or partial counterpart and 1 for delivered parity. NetKAT text, process
text, declaration admission, packet predicates, bounded reachability,
selectors, waypoint and reusable preprocessing each score 0.5. JSON
ingestion and batch CLI/reporting each score 0. For whole-project planning,
weight the completed typed formalization at 65%, functional parity at 25%,
and the outstanding empirical campaign at 10%. Checkpoint 1 raises the four intake core rows (NetKAT and process
text, declaration admission and packet predicates) from 0.5 to 1 and
raw JSON ingestion from 0 to 1. Bounded reachability and selectors both
rise from 0.5 to 1 for implementation readiness. The same weights give
about **85%** overall, with differential acceptance still pending. These are readiness estimates with stated weights, not measured
engineering time or a count of successful differential runs.
